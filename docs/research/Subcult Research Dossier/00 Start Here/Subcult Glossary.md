# Subcult Glossary

**Subcult:** proposed umbrella product. **Subcults:** the existing scene/touring/AT codebase. **Subcult OS:** the existing event-operations codebase. **Studio:** proposed private organizer interface, not an assertion that a fully unified product exists.

**Scene:** cultural community and context. It is not automatically a corporation, workspace, public membership list or financial account.

**Workspace:** private organizational boundary for roles, collaboration and billing. Multiple public hosts do not imply shared workspace access.

**Act:** a creative project or performer identity. A person may participate in several Acts; the Act's touring location is not the person's home.

**Event occurrence:** one actual gathering at a particular time/place. A tour contains appearances across occurrences, not copies of one local event.

**Signal:** proposed/common Subcults language for a versioned invitation or announcement. Delivery permission is separately stored and evaluated.

**Consent scope:** sender, recipient contact point, purpose and channel, with evidence and withdrawal state. Interest in an event is not permission for every co-host to market to the attendee.

**DID:** decentralized identifier used as a stable account reference. A human-readable handle can change. A DID is not proof that an event claim is true.

**PDS:** Personal Data Server, hosting account repository and related services. “Personal” does not mean every record is private.

**Lexicon:** AT schema and API vocabulary. Two applications being built on AT does not guarantee they understand the same records.

**AT URI / CID:** a record address and a content identifier. Address continuity and content revision are different concerns.

**AppView/projection:** a service's derived view for search and application features. It must handle updates, deletion and recovery; it is not the authoritative financial ledger.

**Tap / Jetstream:** synchronization tools with different responsibilities and trust properties; see [[Subcult Sync and Projection Contributions]].

**Spaces:** current experimental permissioned-data work; see [[Subcult Spaces Research]]. Do not equate restricted access with end-to-end encryption.

**Contribution margin:** revenue less specified variable costs. It is not net profit. **ARR:** annualized recurring subscription run rate, not cash in the bank or total ticket sales.

**Qualification:** evidence from a defined test, deployment or real workflow. A file, passing unit test and successful live event are different evidence levels. See [[Subcult Repository Evidence]].
