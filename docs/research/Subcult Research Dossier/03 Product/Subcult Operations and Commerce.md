# Subcult Operations and Commerce

## Start with explicit responsibility

The first operations value is clarity: every important commitment has an owner, deadline, state and relevant event context. A role application is not an accepted assignment. A promised payment is not a completed payout. A public credit is not proof that a duty was performed.

Reuse the existing OS staffing/commitment foundations, but refresh permission and runtime evidence. For the first pilot, support a small number of meaningful roles and a reliable mobile assignment view.

## Commerce coexistence

Keep an external ticket provider authoritative initially. Subcult should show the correct purchase destination and enough metadata to connect the event, but avoid assuming control over refund or admission state.

When an authorized integration is added, preserve provider IDs, webhook provenance, reconciliation status and last successful sync. Never infer valid admission from a public RSVP. Never include redeemable ticket material in AT records.

## Financial closeout

Separate projected budget, committed expense, recorded actual, payable obligation and paid transaction. Give each adjustment an actor, reason and timestamp. “Settlement complete” should mean a defined reconciliation condition, not that a user clicked a button.

The existing OS settlement is an implementation foundation, not proof of full accounting, tax, dispute or multi-entity capability. Treat accounting export as a future scoped integration until demonstrated.

## Event changes

A cancellation should coordinate public status, provider actions, crew notices and outstanding obligations. Those actions can fail independently. Show which succeeded and which need attention.

A reschedule is not automatically a new sale, a refund or a fresh marketing permission. Reuse occurrence identity only under an explicit policy. Keep the former date in the audit record while displaying the current date clearly.

## Price transparency

The FTC's rule covers upfront total-price disclosure for live-event tickets, with specific treatment of allowable exclusions and final payment disclosure. That is a design constraint for a US checkout, not a complete legal specification. [FTC fee-rule FAQ](https://www.ftc.gov/business-guidance/resources/rule-unfair-or-deceptive-fees-frequently-asked-questions).

Display the required total clearly and obtain a jurisdiction-specific review before commerce launch. Avoid presenting platform-only fees as the buyer's full cost.

## Night-of risk

Rehearse connectivity loss, stale roster, refunded ticket, duplicate scan, device loss and staff removal. If offline capability is not proven, use the provider's qualified scanner and keep Subcult's role to coordination. A manual fallback requires an accountable person and post-event reconciliation.
